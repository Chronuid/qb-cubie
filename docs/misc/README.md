# Konzepte, Experimente und Hintergrund

Die Ablage enthält unterschiedliche Dokumentarten. Ein Konzept beschreibt auch
angestrebtes Verhalten; ein Experiment belegt nur den tatsächlich untersuchten
Stand. Für die Produktnutzung gelten die [Leitfäden](../README.md).

| Einstieg | Zweck |
| --- | --- |
| [Offene Punkte](OFFENE_PUNKTE_Benchmarks-Agenten.md) | Gemeinsamer Stand der noch fehlenden Umsetzung und Nachweise; trennt Pflichtpunkte und optionale Erweiterungen. |
| [Benchmark-Konzept](BENCHMARK_KONZEPT.md) | Zielbild, Methodik und phasenbezogener Umsetzungsstand der Benchmark-Infrastruktur. |
| [SWE-bench-Loader](SWE_BENCH_LOADER_ANFORDERUNGEN.md) | Anforderungen und EBT-Vertrag für den implementierten Import und Reparaturbetrieb; reale Integrationsnachweise stehen aus. |
| [Agentenkonzept](AGENTEN_KONZEPT.md) | Rollenadapter, Ausführungsgrenzen und Abnahme der Ollama-Agenten. |
| [Agentenmessung §5.5](EXPERIMENT_Agenten-5-5.md) | Neuere echte explorative Messreihe beider Rollen. Keine offizielle Referenzaufnahme oder allgemeine Leistungsaussage. |
| [Nutzungsexperiment §10.3](EXPERIMENT_Benchmark-10-3.md) | Historischer Nutzungstest des früheren Developer-Beispiels; damalige Mängel sind nicht automatisch heutige Produktfehler. |
| [Entwicklungsnachweise](../../tests/docs_tmp/README.md) | Kriterienmatrizen, ursprüngliche Rotphasen und spätere Implementierungsprüfungen. |

Die übrigen Texte – *Clean-Code-Pragmatism*, *Die Suchmaschine von Babel*,
*Erweitertes PBT* und *FP-OOP-Isomorphismus* – sind Hintergrundüberlegungen.
Sie sind keine verbindlichen API-Verträge oder Nachweise implementierter Funktionen.
